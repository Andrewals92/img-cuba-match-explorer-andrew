# Cuba Match Explorer v4.2

Communications and monitoring upgrade of GitHub main `bca0e383bf7e146592cb25a0529bc30cd3dfb3bc`, preserving static HTML/CSS/vanilla JavaScript, Supabase Auth, existing workspaces and historical imports.

## Included

- Private Notification Center: unread badge, unread/all filters, paginated history, one/all read controls, trusted internal links. Content creation remains server-only; users can update only their own read state.
- Explicit preferences: app/email/push, Radar/watchlist, private interview reminders at 24h/2h, follow-up, IANA timezone, quiet hours, immediate/daily/weekly program alerts.
- Public New Program Radar: specialty/state/detection-date filters, stable program UUID profiles, save and alert actions. A first monitored canonical discovery is Recently Added; initial specialty dataset population is not an alert. Detection is not evidence of open positions or accreditation date.
- Existing ACGME monitor extended with up to ten saved-program status checks per run. Initial status observation establishes baseline; status/effective-date changes create revisioned update events. Formatting changes do not.
- Saved-program mute controls; current-month community activity notices use the existing suppressed >=3 contributor timeline. No alert for single-applicant increments. Existing >=5 characteristics and >=3 Match protections remain.
- Trusted server dispatcher with canonical app notifications, outbox, leased claims, bounded retries, provider idempotency, per-device success tracking, terminal push-device disabling, generic lock-screen content, safe operational counts/codes.
- Service worker v4.2 with push and constrained click handling, preserving same-origin static caching and excluding API traffic.

## Infrastructure

Migrations 020–029 are additive/forward-only. Existing migrations 002–019 were not rerun or renumbered. `notification-dispatcher` v7 and `acgme-program-monitor` v5 deployed from version-controlled source. A five-minute cron creates notifications and invokes the dispatcher; the original ten-minute ACGME cron remains.

VAPID credentials are generated by the backend and retained in a non-exposed, deny-all private table. Only its public key is available to signed-in clients. Cron authentication token and private VAPID key never pass through frontend, repository, artifact or tool logs.

## Readiness boundary

In-app, Radar, preferences and server scheduling are implemented. Server VAPID initialization and dispatcher HTTP 200 are verified. Real browser push permission/subscription/receipt with the app backgrounded still require supported-device acceptance. Email code uses Resend only after `RESEND_API_KEY`, `NOTIFICATION_EMAIL_FROM`, and verified-domain flag are configured server-side. Resend is connected and cubamatchexplorer.org is verified; its server sending credential is now stored privately. Dispatcher email readiness is true; SMTP for Auth is configured. SPF/DKIM verification is confirmed and DMARC is in monitoring mode. Provider acceptance and actual receipt of new production emails are not yet claimed. The owner registered cubamatchexplorer.org and cubamatchexplorer.com; both connect to the existing production project, with .com redirecting permanently to .org.
